# 发布文章 Skill 分类与标签增强设计

## 概述

本次增强目标是在现有“发布文章” skill 基础上，为生成的文章自动补齐 `category` 和 `tags`。分类优先从固定分类池中匹配；如果没有找到合适分类，则基于文章标题和内容总结一个短分类。标签不使用固定池，而是从文章标题和正文中自由总结 2~3 个核心标签。

该增强不改变现有 skill 的主流程，不引入外部 AI 服务，不增加新的用户参数，只在现有脚本内部增加自动归类与标签生成逻辑，并写入 frontmatter。

## 目标与非目标

### 目标
- 在文章缺少分类时自动生成 1 个 `category`。
- 分类优先从固定分类池中匹配。
- 固定池无法匹配时，自动总结一个短分类。
- 自动生成 2~3 个 `tags`。
- 标签根据标题和正文自由总结，不使用固定标签池。
- 将生成结果写入 frontmatter。
- 保持现有发布流程、输出格式和双模式能力不变。

### 非目标
- 不引入外部模型或远程 AI 服务来生成分类和标签。
- 不新增 `--category` 或 `--tags` 参数。
- 不引入独立配置文件维护分类池。
- 不对文章正文做摘要改写。
- 不覆盖未来可能存在的手动分类/标签输入。

## 现状

当前发布脚本 `scripts/publish-article-from-url.mjs` 在写入 frontmatter 时固定输出：
- `category: ''`
- `tags: []`

当前内容 schema `src/content/config.ts` 已允许：
- `category: string`
- `tags: string[]`

因此这次增强只需要补充生成逻辑，不需要修改内容 schema。

## 分类池

首版固定分类池如下：

- `后端`
- `前端`
- `AI`
- `数据库`
- `运维`
- `架构`
- `随笔`

该分类池保持小而稳定，避免站点分类过碎。

## 分类匹配规则

### 匹配优先级
分类生成按以下顺序执行：

1. 标题关键词匹配
2. 正文关键词匹配
3. 固定池匹配失败时，回退到自由总结分类

### 标题优先
标题是第一优先级，因为它最浓缩文章主题。

例如：
- 命中 `Agent`、`RAG`、`MCP`、`LLM`、`提示词`、`大模型`、`智能体` → `AI`
- 命中 `React`、`Vue`、`CSS`、`浏览器`、`组件` → `前端`
- 命中 `Java`、`Spring`、`Go`、`Node`、`接口`、`服务`、`后端` → `后端`
- 命中 `MySQL`、`Redis`、`SQL`、`索引`、`事务` → `数据库`
- 命中 `Docker`、`K8s`、`Kubernetes`、`CI`、`CD`、`部署`、`监控`、`运维` → `运维`
- 命中 `架构`、`设计模式`、`系统设计`、`重构`、`高可用`、`分布式` → `架构`
- 命中 `随笔`、`感想`、`心得`、`总结` → `随笔`

### 正文匹配
如果标题不明显，再扫描正文内容中的分类关键词。

实现方式保持简单稳定：
- 使用固定规则表
- 统计每个分类命中的关键词次数
- 命中次数最高的分类胜出

### 冲突处理
如果多个分类都命中：
1. 标题命中优先于正文命中
2. 更聚焦主题优先于更宽泛主题
3. 若文章明显围绕 AI 工程话题，即使提到后端，也优先归类为 `AI`

### 回退自由总结
如果固定分类池无法明显命中，则允许自动总结一个分类。

约束如下：
- 只生成 1 个分类
- 尽量控制在 2~6 个字
- 风格像栏目名，而不是完整句子
- 不带多余标点

示例：
- `工程实践`
- `开发工具`
- `性能优化`

分类匹配失败不应导致发布失败。

## 标签生成规则

### 生成原则
标签不使用固定标签池，而是从内容中自由总结。

### 来源优先级
1. 标题中的核心技术词
2. 正文前几段中的高频技术词
3. 与分类相关但更细粒度的主题词

### 数量规则
- 最少 2 个
- 最多 3 个
- 如果只能稳定提取 2 个，则不强凑第 3 个

### 过滤规则
生成标签时应过滤：
- 与分类完全相同的词
- 重复词
- 空字符串
- 过于空泛的词，例如：
  - `技术`
  - `开发`
  - `教程`
  - `文章`
  - `总结`
- 过长、像句子的短语

### 失败回退
如果标签提取不足 3 个，不算失败。
如果标签全部提取失败，应回退生成 2 个兜底标签，但仍应尽量贴近文章主题。

标签生成失败不应单独中断整篇发布流程，只要能产出合理的 2 个标签即可继续。

## 实现结构

本次增强仅修改现有脚本：
- `scripts/publish-article-from-url.mjs`

不新增新的执行脚本或独立配置文件。

### 新增函数职责
建议在现有脚本中增加以下逻辑单元：

#### 分类规则常量
- `CATEGORY_RULES`
- 负责维护固定分类池与关键词映射

#### 分类检测函数
- `detectCategory(title, markdown)`
- 根据标题、正文和规则表输出最终分类

#### 标签生成函数
- `generateTags(title, markdown, category)`
- 从标题和正文中提取 2~3 个标签

#### frontmatter 写入函数增强
当前函数：
- `buildPostContent(title, url, markdown)`

增强后：
- `buildPostContent(title, url, markdown, category, tags)`

并将 `category` 与 `tags` 写入 frontmatter。

## 写入规则

### frontmatter 更新目标
当前 frontmatter 中：
- `category` 为空字符串
- `tags` 为空数组

增强后写入为实际生成值，例如：

```yaml
category: 'AI'
tags: ['Agent', 'RAG', 'MCP']
```

### 写入时机
执行顺序更新为：
1. 抓取文章
2. 生成 Markdown
3. 自动生成分类
4. 自动生成标签
5. 执行 `pnpm new-post`
6. 将分类、标签和正文统一写入 frontmatter 与文件内容

## 异常处理

### 分类无法命中固定池
- 不失败
- 进入自由总结分类分支
- 继续发布

### 标签少于 3 个
- 不失败
- 允许只生成 2 个

### 分类或标签含非法字符
- 先清洗再写入
- 去除首尾空格、重复项、多余标点
- 清洗后为空则继续回退生成

### 标签全部提取失败
- 不直接失败
- 尝试生成 2 个兜底标签
- 仍应尽量贴合主题

## 验证标准

至少验证以下场景：

1. 固定分类池命中成功
   - 例如 Agent / RAG / MCP 文章应归类为 `AI`
   - 标签应生成 2~3 个核心技术词

2. 标题不明显但正文命中成功
   - 例如正文包含 MySQL / Redis / SQL 等关键词
   - 应归类为 `数据库`

3. 固定池不命中时回退自由总结
   - 分类不应为空
   - 分类应是短栏目名，而不是描述句

4. 标签不足时不强凑
   - 若只能稳定提取 2 个标签，应允许仅写入 2 个

## Skill 文案更新

需要同步更新 `data/skills/publish-article-from-url.md`，补充说明：

- skill 会自动补齐 `category` 和 `tags`
- 分类优先从固定分类池中匹配
- 若没有合适分类，会自动总结短分类
- 标签会根据文章内容自由生成 2~3 个

## 约束与取舍

首版增强只做：
1. 固定分类池匹配
2. 自由分类回退
3. 自由标签生成
4. frontmatter 写入 category / tags

本次不做：
- `--category`
- `--tags`
- 自定义分类配置文件
- 外部 AI 服务生成分类和标签

这样可以把改动控制在现有 skill 的自然延伸范围内，保持自动化体验，同时避免分类体系失控。
